RULE SYNTAX

(rule COMMAND EFFECT)

COMMAND:  String or (or STRING...)
EFFECT:   Arg pattern, combinator, conditional, or terminal

Each rule takes exactly one body effect. Use combinators for complex logic.

Examples:
  (rule "ls" (effect :allow))

  (rule "rm"
    (if (anywhere "-r" "--recursive")
        (effect :ask "Recursive deletion")
      (effect :allow)))

EFFECTS

Terminal Effects (return a decision):
  (effect :allow)
  (effect :ask "Reason")
  (effect :deny "Reason")

Arg Patterns (return Allow on match, Nil otherwise):
  (positional PAT...)         Match by position (flags skipped)
  (exact PAT...)              Like positional, no extra args allowed
  (anywhere PAT...)           Token appears anywhere in argv
  (forbidden PAT...)          None of these tokens in argv
  (flag NAME)                 Named flag is present (any spelling)
  (parameter NAME FORM)       Match the value of a named flag against FORM

Flag and Parameter Names:
  "x"                         Length 1 -> short flag (-x), matches in
                              combined clusters too (`-rfx`).
  "force"                     Length >1 -> long flag (--force), matches
                              `--force` and `--force=VAL`.
  ["f" "force"]               Vector -> match either spelling.

  (parameter NAME FORM) consumes the flag and its value, so sibling
  positional matchers see the remaining args correctly. The flag is also
  implicitly added to the active :flags-with-values list, so the
  tokeniser groups -X VAL even without an (args-style ...) declaration.

  FORM is either:
    (may-i *)         Parse the value as a command line and recurse
    (regex "...")     Regex match the value as a single token
    "literal"         Exact value match
    *                 Match any value (parameter is just a presence check)

  Examples:
    (rule "rm"   (and (not (flag "r"))   (effect :allow)))
    (rule "git"  (and (positional "push") (not (flag ["f" "force"])) (effect :allow)))
    (rule "curl" (and (parameter ["X" "request"] "POST") (effect :allow)))
    (rule "bash" (parameter "c" (may-i *)))     ; recurse into bash -c VAL

Expression Patterns (match a single token):
  "string"                    Literal match
  *                           Wildcard (matches anything)
  (regex "PATTERN")           Regex match
  (or PAT...)                 Match any
  (and PAT...)                Match all
  (not PAT)                   Negate
  [:key *]                    Bind matched value as fact

Quantifiers (wrap a positional pattern):
  EXPR                        Exactly one (default)
  (? EXPR)                    Zero or one
  (+ EXPR)                    One or more
  (* EXPR)                    Zero or more

Combinators:
  (and EFFECT...)             All must succeed (short-circuits on Nil)
  (or EFFECT...)              First non-Nil wins
  (not EFFECT)                Swap Allow <-> Nil; pass Ask/Deny

Conditionals (predicate controls branching):
  (when PRED EFFECT)          Effect if predicate matches
  (unless PRED EFFECT)        Effect if predicate doesn't match
  (if PRED THEN ELSE)         If-then-else
  (cond ((PRED EFF)...) (else EFF))   Multi-way branch

  Predicates: (fact? ...), arg patterns, named refs, (and/or/not ...)

Recursive Evaluation:
  (positional . (may-i *))              Eval rest as command (sudo)
  (positional [:host *] . (may-i *))    Bind host, eval rest (ssh)

  (may-i *) automatically adds the wrapper command name to the :via fact set.
  For example, (rule "sudo" (positional . (may-i *))) sets :via to "sudo".
  Query with (fact? [:via "sudo"]).

FACTS

Facts provide runtime context via --fact or automatic binding (see may-i above).

Two forms:
  Presence:  :ci                        Key exists (no value)
  Value:     [:env "prod"]              Key with value

Query with (fact? ...):
  (fact? :ci)                            ; presence check
  (fact? [:env "prod"])                  ; exact value
  (fact? [:host (regex "^prod-")])       ; regex match
  (and (fact? A) (fact? B))              ; combined

Pass facts to eval:
  may-i eval --fact :ci --fact :env=prod 'kubectl get pods'

NAMED PREDICATES

Define reusable predicates:
  (define prod-host
    (fact? [:ssh/host (regex "^prod-")]))

Use in rules:
  (rule "kubectl"
    (if prod-host
        (effect :deny "No prod access")
      (effect :allow)))

CHECKS

Write tests at top-level or inside rules:
  (check :allow "ls -la"
         :deny "rm -rf /")

With facts:
  (check (with-facts [[:env "prod"]]
           :deny "kubectl get pods")
         (with-facts [[:env "dev"]]
           :allow "kubectl get pods"))

Validate with: may-i check

LOAD

Split config across files:
  (load "rules/git.lisp")              Load a file (relative to config dir)
  (load "rules/*.lisp")                Glob pattern, loaded in lexical order

Paths resolve relative to the file containing the load form.
Recursive loads supported. Circular loads detected and rejected.

SAFE ENV VARS

Whitelist environment variables for shell expansion:
  (safe-env-vars "HOME" "PWD" "USER" "SHELL" "EDITOR")

TOKENISATION

Each program's argv is split into flags, flag values, and positional
arguments under a tokenisation profile. The default is :gnu; other profiles
are opted into per program with `args-style`.

  (args-style PROGRAM :PROFILE [:flags-with-values (FLAG ...)])

Profiles:
  :gnu              short -x, long --foo, combine -rf -> -r -f, --foo=val
                    or --foo val. Default when no args-style is declared.
  :single-dash-long every -foo is a single long flag; no combining.
                    Used by tools like find, go, terraform, java.
  :legacy-bundle    first non-dashed alpha-cluster is a flag bundle
                    (e.g. tar xvzf -> -x -v -z -f); subsequent tokens
                    follow :gnu rules.
  :key-value        key=value tokens are flag-equivalent; everything else
                    is positional. Used by tools like dd.

:flags-with-values lists additional flags that consume the next arg as a
value. Layers on top of any profile.

Examples:
  (args-style "find"    :single-dash-long)
  (args-style "tar"     :legacy-bundle)
  (args-style "dd"      :key-value)
  (args-style "kubectl" :gnu :flags-with-values ("-n" "--namespace"))

The trace surfaces the resolved profile per evaluation.

Baseline (built-in, overridden by user `args-style` declarations):
  find, go, terraform   :single-dash-long
  tar                   :legacy-bundle
  dd                    :key-value
